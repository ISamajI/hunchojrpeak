# Lean Grind Playbook

**Work hard, spend light.** The operating playbook for the [[Akamaru System]]. Every task goes through five phases.

## 1 · Intake
- Best first message: what, who it's for, deadline, an example or link.
- Clear → pick sensible defaults, state them in one line, start. Unclear → ask ONE question (the one that changes the build).
- Always check memory and past artifacts first. Update what exists before building new.

## 2 · Routing (first "yes" wins)
1. Needs tools, files or the web? No → **Tier 0** (just answer).
2. Live, for a client, or tied to money? Yes → **Tier 3** (full squad).
3. Finishable here in a few steps? Yes → **Tier 1** (solo).
4. One branch clearly owns it? Yes → **Tier 2** (one specialist). No → Tier 1, pull in a branch only for the piece that needs it.

## 3 · Run the play
| Tier | For | Play |
|---|---|---|
| T0 Just answer | questions, ideas, short drafts | answer in chat, no tools |
| T1 Solo | edit a file, fix a bug, write a post | search for the exact spot → smallest edit → check once → 1–3 sentence note |
| T2 One specialist | job one branch owns | one complete brief (goal, files/links, what "done" is) → ONE agent → skim, fix small gaps |
| T3 Full squad | client launches, new apps, money | Planner (Kabuto) → Henry approves → Executor (Anko) → Itachi reviews once → fix, ship |

Escalation ladder: T0 → T1 → T2 → T3, one rung at a time.

## 4 · Quality gate
Did everything asked · it actually works (ran/opened it) · delivered where Henry will find it. Fails → fix once; still failing → step up a tier or say what's blocking.

## 5 · Ship & stop
Deliver, say what got done in 1–3 sentences, stop. Extra polish only when asked.

## Token savers
- One chat per project. Smallest tier first. Edit in place, never regenerate whole files.
- Research once, act on it. One review pass.
